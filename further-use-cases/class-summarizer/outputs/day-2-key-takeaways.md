# Day 2 — Top 10 Key Takeaways

_Short summary of the Day 2 transcript ([`day_2_transcript.md`](../inputs/day_2_transcript.md)), covering the recorded session. Speakers are identified in the source transcript._

1. **Day 2 moves from chat into file-based work.** The desktop app's Code area was used as an introduction to working with a repository, while the terminal and an IDE were presented as alternatives.

2. **There are several ways to get a repository.** Download a ZIP, clone it with Git, or ask the desktop app to clone it into a selected folder. Open a new session in the cloned folder before working.

3. **Use a dedicated project directory.** A folder such as `Development/` keeps permissions and files contained. Do not grant access to an entire desktop or drive.

4. **Git records versions of a project.** A commit is a named snapshot of selected changes. The `.git` folder stores the local history; GitHub can store a shared or backup copy.

5. **Git is useful even without programming.** It provides history, a way to review changes, and a way to restore an earlier version of a document or folder.

6. **Keep private material out of public repositories.** Do not commit passwords, API keys, student records, or other restricted data. Use a `.gitignore` file and check the repository before sharing it.

7. **Commit small, meaningful changes.** A short message makes the history easier to understand and gives you more points to return to if a later change is wrong.

8. **A pull request is a review step.** It proposes changes to a shared branch so someone can inspect them before merging them into the main branch.

9. **Repositories can be starting points.** A public repository may contain texts, data, scripts, or course materials. Check its license, contents, and trustworthiness before using it.

10. **Give the model exact file paths.** Pointing to one file is faster and safer than asking it to search the whole repository. In a code workspace, you can also edit files directly and inspect the resulting diff.

## Secondary points worth keeping

- Some computers need Git installed separately; a package manager can help with that setup.
- HTML files can be opened in a browser directly from the project folder.
- Large videos and image collections may need separate storage or processing.
- The next session introduced project instructions and reusable skills.
