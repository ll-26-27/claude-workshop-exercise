# Day 3 — Top 10 Key Takeaways

_Short summary of the Day 3 transcript ([`day_3_transcript.md`](../inputs/day_3_transcript.md)), covering the recorded session. Speakers are identified in the source transcript._

1. **Start each session in the correct project folder.** Clone or download the repository, then open a new session with that folder selected.

2. **Use `git pull` to update a cloned repository.** A pull brings changes from GitHub into the local copy; a ZIP download does not provide the same update path.

3. **Search for existing repositories before starting from zero.** A repository may contain useful source texts, data, scripts, or methods for a course or research project.

4. **Treat public repositories as untrusted inputs.** Check the owner, license, files, and scripts before opening or running anything. Do not assume a repository is safe because it appears in search results.

5. **Keep large files separate from the working text.** Videos, images, and large datasets can exceed local or service limits. Use appropriate storage and connect to them deliberately.

6. **A project folder makes repeated work easier.** Keep inputs, operations, and outputs together, with clear names and a short project description.

7. **Skills package a repeated operation.** A skill can describe the inputs it expects, the steps it should follow, and the output it should create.

8. **Project instructions provide shared context.** A `CLAUDE.md` file can explain the project structure, conventions, and checks that should apply in every session.

9. **Use templates for consistent documents.** The handout exercise showed how a text source can be turned into a reusable document layout instead of being reformatted by hand each time.

10. **Review generated work and its permissions.** Check the source, the model's plan, the files it changed, and the final output. Approve only actions you understand.

## Secondary points worth keeping

- Model names, limits, and usage allowances change; check the current account settings.
- Keep sensitive data out of prompts, repositories, and generated examples.
- If a model refuses or produces a strange result, inspect the task and the supplied context before retrying.
