Day 1 — Top 10 Key Takeaways

Short summary of the Day 1 transcript.

  1. A language model predicts text; it does not think like a person. Text is split into tokens and represented as numbers.
  2. Use tools for exact results. The multiplication demonstration showed why a model should call a calculator or Python for arithmetic.
  3. Check confident answers. In the Coriolanus example, the model changed its answer after the text was supplied.
  4. Ask for a data-backed artifact. A CSV plus an interactive chart is more useful than an image that only looks like a chart.
  5. Good source material matters. Lesson materials, handwriting, and video transcripts shaped the demonstrations.
  6. A new chat has limited working context. Start a new chat or summarize when a thread becomes long.
  7. Keep high-value context in files. Source documents and instructions should be easy to find.
  8. Limit file access to one folder. Use a dedicated project folder rather than the desktop or an entire drive.
  9. Batch work is possible when the task is explicit. The recipe-photo demonstration combined renaming, transcription, research, and HTML generation.
  10. Plan projects as inputs, operations, and outputs. Separate source files, processes, and expected results so work can be repeated and checked.

Secondary points

  • Plain text is easy for models to inspect and reuse.
  • Review remains the instructor's job.
  • Interactive layouts may need manual correction.
  • Agreement is not evidence that a claim is correct.
