# Day 1 — Top 10 Key Takeaways

_Short summary of the Day 1 transcript ([`day_1_transcript.md`](../inputs/day_1_transcript.md)), covering the recorded session. Speakers are identified in the source transcript._

1. **A language model predicts text; it does not think like a person.** Text is split into tokens and represented as numbers. The model predicts likely next tokens from patterns in its training.

2. **Use tools for tasks that need exact results.** The multiplication demonstration showed why a model should call a calculator or Python for arithmetic instead of relying on pattern matching.

3. **Check confident answers.** In the *Coriolanus* example, the model first denied that a scene existed and then changed its answer after the text was supplied. Confidence and agreement are not evidence.

4. **Ask for a data-backed artifact when the result must be correct.** A CSV plus a generated interactive chart is more useful than an image that only looks like a chart.

5. **The useful work starts with good source material.** Demonstrations included lesson materials, handwriting, and video transcripts. The quality of the supplied course material shaped the result.

6. **A new chat has limited working context.** System instructions, memory, prompts, files, and previous answers all compete for space. Start a new chat or summarize when a thread becomes long.

7. **Put high-value context in the prompt or project files.** A model can lose track of material in the middle of a long conversation, so keep the source documents and instructions easy to find.

8. **Give file tools access to one specific folder.** Cowork and Code can read or write local files. Use a dedicated project folder rather than the desktop or an entire drive.

9. **Batch work is possible when the files and task are explicit.** The recipe-photo demonstration combined renaming, transcription, background research, and HTML generation. The same pattern can apply to course materials.

10. **Plan a project as inputs, operations, and outputs.** List the source files, describe the operations or prompts, and name the files or results you expect. Keep those parts separate so the work can be repeated and checked.

## Secondary points worth keeping

- Markdown and other plain-text formats are easy for models to inspect and reuse.
- A model can draft a prompt, critique it, and revise it; review remains the instructor's job.
- Interactive layouts and spatial positioning may still need manual correction.
- Sycophantic agreement is a model behavior, not confirmation that a claim is correct.
