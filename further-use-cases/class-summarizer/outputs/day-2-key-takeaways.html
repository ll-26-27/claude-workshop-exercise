Day 2 — Top 10 Key Takeaways

Short summary of the Day 2 transcript.

  1. Day 2 moves from chat into file-based work. The desktop app's Code area introduced repositories; terminal and IDE use were alternatives.
  2. There are several ways to get a repository. Download a ZIP, clone with Git, or ask the app to clone it into a selected folder.
  3. Use a dedicated project directory. Keep permissions and files contained.
  4. Git records versions. A commit is a named snapshot; GitHub can store a shared or backup copy.
  5. Git is useful without programming. It provides history, review, and recovery.
  6. Keep private material out of public repositories. Do not commit passwords, keys, student records, or restricted data.
  7. Commit small changes. Short messages make history easier to follow.
  8. A pull request is a review step. It proposes changes before they enter the main branch.
  9. Repositories can be starting points. Check license, contents, and trustworthiness before using them.
  10. Give the model exact file paths. This is faster and safer than searching the whole repository.

Secondary points

  • Some computers need Git installed separately.
  • HTML files open directly in a browser.
  • Large media files may need separate storage.
  • Project instructions and reusable skills were introduced next.
